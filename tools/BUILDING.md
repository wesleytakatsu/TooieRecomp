## 2. ROM Verification & Decompression

### 2.1 Raw Cartridge ROM Verification

Place your cartridge dump at the repository root as `Banjo-Tooie (USA).z64` (git-ignored).

```bash
# Verify using the project helper:
tools/rom_check.sh

# Or verify manually on Linux:
md5sum "Banjo-Tooie (USA).z64"   # 40e98faa24ac3ebe1d25cb5e5ddf49e4
sha1sum "Banjo-Tooie (USA).z64"  # af1a89e12b638b8d82cc4c085c8e01d4cba03fb3
stat -c %s "Banjo-Tooie (USA).z64" # 33554432
```

On Windows (PowerShell):
```powershell
# Verify using the project helper:
python tools/rom_check.py

# Or verify manually:
Get-FileHash -Algorithm MD5 ".\Banjo-Tooie (USA).z64"   # 40E98FAA24AC3EBE1D25CB5E5DDF49E4
Get-FileHash -Algorithm SHA1 ".\Banjo-Tooie (USA).z64"  # AF1A89E12B638B8D82CC4C085C8E01D4CBA03FB3
(Get-Item ".\Banjo-Tooie (USA).z64").Length             # 33554432
```

### 2.2 ROM Extraction (`tools/extract_rom.sh` / `tools/extract_rom.py`)

The game launcher natively accepts both the retail cartridge ROM (`Banjo-Tooie (USA).z64` / `.n64`, decompressing transparently in memory) and the uncompressed ROM image (`decompressed.us.z64`).

However, the recompiler code generator (`recomp` stage) still requires the decompressed ROM file. To extract and decompress the ROM without needing the legacy MIPS compiler kit:

**Linux:**
```bash
tools/extract_rom.sh
# Or via pipeline: tools/build_linux.sh extract
```

**Windows:**
```powershell
.\tools\windows\Build-Tooie.ps1 -Stage Extract
# Or portable Python: python tools/extract_rom.py
```

- **Mechanism:** Builds and runs the vendored ROM decompressor in a temporary directory using host compilers and vendored miniz/fmt shims (no IDO kit needed).
- **Output:** `build-linux/extract/decompressed.us.z64` (Linux) or `build-win/extract/decompressed.us.z64` (Windows).
- **Expected Decompressed Hashes:**
  - Size: `35098224` bytes
  - SHA-1: `af479771ff5e91ce3732f3d84146614ab71d8d79`
- **Launcher Execution:** In `TooieRecompiled`, select either `Banjo-Tooie (USA).z64` or `decompressed.us.z64`.

## 3. Building on Linux (Ubuntu 24.04 / Linux Mint 22)

### 3.1 Host Package Installation

```bash
sudo apt update
sudo apt install -y \
  git cmake ninja-build clang lld pkg-config make g++ python3 \
  libsdl2-dev libfreetype-dev libgtk-3-dev libfmt-dev zlib1g-dev
```

*Note: The normal build is 100% kit-free and has no path restrictions. Only the maintainer-only decomp stage requires a workspace path without `.c` (upstream `ultralib` defect).*

### 3.2 Git Clone (Preserve LF)

```bash
git -c core.autocrlf=false clone https://github.com/wesleytakatsu/TooieRecomp.git
cd TooieRecomp
git config core.autocrlf false
```

Offline integrity of all vendored files can be verified at any time:
```bash
tools/vendor_verify.sh
```

### 3.3 Automated Kit-Free Pipeline Execution

The normal build is **completely kit-free**. It requires no external compiler kit, no MIPS cross-compilers, no ELF, and no network access:

```bash
export TOOIE_ROM="$PWD/Banjo-Tooie (USA).z64"

tools/preflight.sh     # Strict read-only environment check (kit-free)
tools/build_linux.sh   # Default stages: preflight verify extract recomp configure build test package
```

The pipeline executes the following stages sequentially:
1. `preflight`: Verifies offline tools, libraries, and canonical ROM.
2. `verify`: Audits integrity of vendored files against `vendor/MANIFEST.sha256`.
3. `extract`: Runs `tools/extract_rom.sh` to produce `build-linux/extract/decompressed.us.z64` (required by launcher).
4. `recomp`: Compiles vendored `N64Recomp` and generates `RecompiledFuncs/` (420 files) directly from the decompressed ROM and committed `metadata/tooie.us.syms.toml`, then validates against `metadata/recomp-output.sha256`.
5. `configure` + `build`: Compiles `TooieRecompiled` (1159 steps) with Clang and Ninja.
6. `test`: Runs 8 host unit test suites.
7. `package`: Creates the Linux candidate package (`TOOIE_RELEASE_VERSION=<ver> tools/package_linux.sh` produces `dist/BanjoTooieRecompiled-v<ver>-Linux-x64.tar.gz`, or dev `BanjoTooieRecompiled-dev-*-Linux-x64.tar.gz`).

4. Verify and smoke-test candidate package:
```bash
# Test isolated sandbox launch (verifies process liveness; smoke_package expects a directory):
tools/smoke_package.sh dist/BanjoTooieRecompiled-*-Linux-x64/BanjoTooieRecompiled

# Verify archive checksums and file manifest:
tools/verify_package.sh dist/BanjoTooieRecompiled-*-Linux-x64.tar.gz
```

### 3.4 Maintainer-Only: Decompilation & Metadata Regeneration (Requires Legacy Compiler Kit)

Normal builds do **not** require this stage. Only maintainers updating decompilation or regenerating recompiler metadata (`metadata/tooie.us.syms.toml` via `tools/generate_metadata.py`) need the legacy IDO/gcc compiler kit:

1. Install maintainer packages: `sudo apt install gcc-mips-linux-gnu binutils-mips-linux-gnu libtoml11-dev python3-venv`.
2. Download the 4 upstream compiler archives into `<kit-dir>` and verify the 34 binaries:
   ```bash
   tools/toolchain_kit.sh verify /path/to/toolchain-kit
   ```
3. Run the maintainer stages:
   ```bash
   export TOOIE_TOOLCHAIN_KIT="/path/to/toolchain-kit"
   tools/preflight.sh decomp
   tools/build_linux.sh decomp
   ```

## 4. Building on Windows 11 x64

The native Windows 11 x64 build pipeline is fully proven on host (`tools\windows\Build-Tooie.ps1 -Stage All`). All stages run natively without WSL or POSIX emulation layers.

### 4.1 Prerequisites (Official Component IDs)

1. **Visual Studio 2022 or newer:**
   Install Visual Studio Community 2026/2022 or Build Tools with the C++ Desktop workload and the following official component IDs (run in an **elevated** terminal because `--passive` requires administrator privileges):
   ```powershell
   winget install --id Microsoft.VisualStudio.2022.BuildTools --source winget --override "--passive --wait --add Microsoft.VisualStudio.Workload.VCTools --add Microsoft.VisualStudio.Component.VC.Llvm.Clang --add Microsoft.VisualStudio.Component.VC.Llvm.ClangToolset --add Microsoft.VisualStudio.Component.VC.CMake.Project --add Microsoft.VisualStudio.Component.Windows11SDK.26100"
   ```
   - Clang compiler: `Microsoft.VisualStudio.Component.VC.Llvm.Clang` (provides `clang-cl` 20.1.8 and `lld-link`)
   - Clang toolset: `Microsoft.VisualStudio.Component.VC.Llvm.ClangToolset`
   - CMake & Ninja: `Microsoft.VisualStudio.Component.VC.CMake.Project`
   - Windows SDK: `Microsoft.VisualStudio.Component.Windows11SDK.26100` (or newer Windows 11 SDK)

   *(Alternatively, you can use the Visual Studio Installer GUI and select "Desktop development with C++", "C++ Clang Compiler for Windows", "MSVC Clang toolset", "C++ CMake tools for Windows", and the Windows 11 SDK).*
2. **Git for Windows:**
   ```powershell
   winget install --id Git.Git -e --source winget
   ```
   *(Git Bash is used only by `tools/vendor_verify.sh` and `tools/package_manifest.sh`).*
3. **Python 3.8+:**
   ```powershell
   winget install --id Python.Python.3.12 -e --source winget
   ```
   *(Reachable as `py -3` or `python`; the Microsoft Store `python3` stub is automatically ignored by build scripts).*
4. **Git Clone with LF:**
   Vendored files must retain byte-exact LF endings:
   ```powershell
   git -c core.autocrlf=false clone https://github.com/wesleytakatsu/TooieRecomp.git
   cd TooieRecomp
   git config core.autocrlf false
   ```

### 4.2 Automated Native Pipeline (`Build-Tooie.ps1`)

Execute the end-to-end native build:

```powershell
.\tools\windows\Build-Tooie.ps1 -Stage All
```

This sequentially runs:
1. `Check`: Verifies compiler, tools, LF line endings, and vendored file integrity.
2. `Extract`: Decompresses retail ROM `Banjo-Tooie (USA).z64` to `build-win\extract\decompressed.us.z64`.
3. `Recomp`: Compiles `N64Recomp.exe` and generates 420 C files in `RecompiledFuncs/` (byte-identical to Linux baseline).
4. `Configure` + `Build`: Compiles `TooieRecompiled.exe` using `clang-cl` and `lld-link` via Ninja (copies `SDL2.dll`, `dxil.dll`, `dxcompiler.dll`).
5. `Test`: Runs required host test suites (9/9 PASS, 15/15 extra PASS with `-AllTests`).
6. `Package`: Creates distribution archive `dist\BanjoTooieRecompiled-v<ver>-Windows-x64.zip` (with `-ReleaseVersion <ver>`) or `dist\BanjoTooieRecompiled-dev-<desc>-Windows-x64.zip` (+ `.sha256`).

Individual stages can also be executed:

```powershell
.\tools\windows\Build-Tooie.ps1 -Stage Check
.\tools\windows\Build-Tooie.ps1 -Stage Extract [-Rom <path>]
.\tools\windows\Build-Tooie.ps1 -Stage Recomp [-Jobs N]
.\tools\windows\Build-Tooie.ps1 -Stage Verify
.\tools\windows\Build-Tooie.ps1 -Stage Configure [-BuildDir <path>]
.\tools\windows\Build-Tooie.ps1 -Stage Build [-Jobs N]
.\tools\windows\Build-Tooie.ps1 -Stage Test [-AllTests]
.\tools\windows\Build-Tooie.ps1 -Stage Package [-ReleaseVersion <ver>]
```

- **Options:**
  - `-Jobs N`: Concurrency level (default: host logical CPU count).
  - `-BuildDir <path>`: Build tree location (default: `build-win`).
  - `-Rom <path>`: Override path to retail ROM for `Extract`.
  - `-AllTests`: Build all test targets and execute argument-free tests (15/15 extra PASS, 5 driver targets SKIP).
- **Outputs:** `build-win\TooieRecompiled.exe` with bundled DLLs.
- **Verification:** `python tools/verify_package.py dist\BanjoTooieRecompiled-*-Windows-x64*.zip`.
- **Running:** Execute `.\run-tooie.ps1` or double-click `build-win\TooieRecompiled.exe`. The launcher accepts both retail cartridge ROMs (`.z64`/`.n64`) and decompressed images.

### 4.3 Legacy Fallback: `ImportGenerated`

If you need to bypass local recompiler generation, you can import pre-generated `RecompiledFuncs` from a Linux/WSL2 build using the legacy stage:

```powershell
.\tools\windows\Build-Tooie.ps1 -Stage ImportGenerated -GeneratedFrom C:\path\to\RecompiledFuncs
```

*(This is preserved solely as a fallback; native recompiler generation via `-Stage Recomp` is now fully supported and recommended).*

## 5. Distribution & Licensing

- **Public Release Policy:** Binary releases are published publicly on GitHub Releases (like Zelda64Recomp and BanjoRecomp). Packages contain machine-translated code compiled into the executable, with NO game assets and NO ROM. Graphics, audio, and game data are read from the user's legally acquired ROM at runtime. `RecompiledFuncs/` C sources are untracked in git and never published as source.
- **Zero Game Assets Versioned:** The repository contains no ROM dumps, textures, level geometry, or audio banks.
- **Native UI Resources:** All previously completed native UI assets, animations, icons, character vector art, typography fonts (including `Suplexmentary Comic NC.ttf`, `InterVariable.ttf`, `NotoEmoji-Regular.ttf`, and `promptfont.ttf`), and the original 7300x2450 Tooie logo are vendored locally in `assets/` and `ui_assets/` (managed on every build by CMake target `TooieUIAssets`). License notices and provenance are tracked honestly (SIL OFL 1.1 notices; zlib controller DB; origin and unverified license status of Suplexmentary Comic NC preserved without blocking restoration). Rows marked UNKNOWN/UNVERIFIED in the third-party manifest remain open owner items to clear; TooieRecomp itself has no LICENSE file (open owner decision).
- Detailed legal terms: See [Asset and Licensing Manifest](../docs/specs/Tooie/asset-and-licensing-manifest.md).
