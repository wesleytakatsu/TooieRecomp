## 2. ROM Verification & Decompression

### 2.1 Raw Cartridge ROM Verification

Place your cartridge dump at the repository root as `Banjo-Tooie (USA).z64` (git-ignored).

```bash
# Verify using the project helper:
tools/rom_check.sh

# Or verify manually on Linux:
md5sum "Banjo-Tooie (USA).z64"   # 40e98faa24ac3ebe1d25cb5e5ddf49e4
sha1sum "Banjo-Tooie (USA).z64"  # af1a89e12b638b8d82cc4c085c8e01d4cba03fb3
stat -c %s "Banjo-Tooie (USA).z64" # 33554432
```

On Windows (PowerShell):
```powershell
Get-FileHash -Algorithm MD5 ".\Banjo-Tooie (USA).z64"   # 40E98FAA24AC3EBE1D25CB5E5DDF49E4
Get-FileHash -Algorithm SHA1 ".\Banjo-Tooie (USA).z64"  # AF1A89E12B638B8D82CC4C085C8E01D4CBA03FB3
(Get-Item ".\Banjo-Tooie (USA).z64").Length             # 33554432
```

### 2.2 ROM Extraction (`tools/extract_rom.sh`)

The game engine and launcher **strictly require** the uncompressed ROM image (`decompressed.us.z64`). The retail cartridge ROM is compressed and cannot be run directly (the launcher rejects cartridge hash `00F70DE5F2D70EA2`).

To extract and decompress the ROM without needing the legacy MIPS compiler kit:

```bash
tools/extract_rom.sh
# Or: tools/build_linux.sh extract
```

- **Mechanism:** Builds vendored `decomp/tools/rom_decompressor` in a temporary directory using host `g++`, `make`, `libfmt-dev`, and `zlib1g-dev` (no IDO kit needed).
- **Output:** `build-linux/extract/decompressed.us.z64`.
- **Expected Decompressed Hashes:**
  - Size: `35098224` bytes
  - SHA-1: `af479771ff5e91ce3732f3d84146614ab71d8d79`
- **Launcher Execution:** In `TooieRecompiled`, select `build-linux/extract/decompressed.us.z64`.

## 3. Building on Linux (Ubuntu 24.04 / Linux Mint 22)

### 3.1 Host Package Installation

```bash
sudo apt update
sudo apt install -y \
  git cmake ninja-build clang lld pkg-config make g++ python3 \
  libsdl2-dev libfreetype-dev libgtk-3-dev libfmt-dev zlib1g-dev
```

*Note: The normal build is 100% kit-free and has no path restrictions. Only the maintainer-only decomp stage requires a workspace path without `.c` (upstream `ultralib` defect).*

### 3.2 Git Clone (Preserve LF)

```bash
git -c core.autocrlf=false clone https://github.com/wesleytakatsu/TooieRecomp.git
cd TooieRecomp
git config core.autocrlf false
```

Offline integrity of all vendored files can be verified at any time:
```bash
tools/vendor_verify.sh
```

### 3.3 Automated Kit-Free Pipeline Execution

The normal build is **completely kit-free**. It requires no external compiler kit, no MIPS cross-compilers, no ELF, and no network access:

```bash
export TOOIE_ROM="$PWD/Banjo-Tooie (USA).z64"

tools/preflight.sh     # Strict read-only environment check (kit-free)
tools/build_linux.sh   # Default stages: preflight verify extract recomp configure build test package
```

The pipeline executes the following stages sequentially:
1. `preflight`: Verifies offline tools, libraries, and canonical ROM.
2. `verify`: Audits integrity of vendored files against `vendor/MANIFEST.sha256`.
3. `extract`: Runs `tools/extract_rom.sh` to produce `build-linux/extract/decompressed.us.z64` (required by launcher).
4. `recomp`: Compiles vendored `N64Recomp` and generates `RecompiledFuncs/` (420 files) directly from the decompressed ROM and committed `metadata/tooie.us.syms.toml`, then validates against `metadata/recomp-output.sha256`.
5. `configure` + `build`: Compiles `TooieRecompiled` (1159 steps) with Clang and Ninja.
6. `test`: Runs 8 host unit test suites.
7. `package`: Creates the Linux candidate package.

4. Verify and smoke-test candidate package:
```bash
# Test isolated sandbox launch (verifies process liveness; smoke_package expects a directory):
tools/smoke_package.sh dist/TooieRecompiled-linux-x86_64-*-private-local

# Verify archive checksums and file manifest:
tools/verify_package.sh dist/TooieRecompiled-linux-x86_64-*-private-local.tar.gz
```

### 3.4 Maintainer-Only: Decompilation & Metadata Regeneration (Requires Legacy Compiler Kit)

Normal builds do **not** require this stage. Only maintainers updating decompilation or regenerating recompiler metadata need the legacy IDO/gcc compiler kit:

1. Install maintainer packages: `sudo apt install gcc-mips-linux-gnu binutils-mips-linux-gnu libtoml11-dev python3-venv`.
2. Download the 4 upstream compiler archives into `<kit-dir>` and verify the 34 binaries:
   ```bash
   tools/toolchain_kit.sh verify /path/to/toolchain-kit
   ```
3. Run the maintainer stages:
   ```bash
   export TOOIE_TOOLCHAIN_KIT="/path/to/toolchain-kit"
   tools/preflight.sh decomp
   tools/build_linux.sh decomp
   ```

## 4. Building on Windows 11 x64 (Native Host Pending)

### 4.1 Prerequisites (Official Component IDs)

1. **Git for Windows:** Official installer from `https://git-scm.com/download/win` or via `winget install --id Git.Git -e --source winget`.
2. **Python 3.8+:** Reachable from Git Bash as `python3`, `python`, or `py -3` (required for vendor integrity audit; Windows Store stub does not count).
3. **Visual Studio 2022 Build Tools:**
   Install with official component IDs per Microsoft documentation:
   ```powershell
   winget install --id Microsoft.VisualStudio.2022.BuildTools --source winget --override "--passive --wait --add Microsoft.VisualStudio.Workload.VCTools --add Microsoft.VisualStudio.Component.VC.Llvm.Clang --add Microsoft.VisualStudio.Component.VC.CMake.Project --add Microsoft.VisualStudio.Component.Windows11SDK.26100"
   ```

### 4.2 Pathway A: Direct Private Transfer (Recommended — No WSL Needed)

Compile natively on Windows using a pre-generated C bundle and the decompressed ROM transferred from Linux:

1. Transfer `TooieRecomp-generated-private-local.tar.gz` (contains the 420 generated C/C++ files) and `decompressed.us.z64`.
2. Clone repository on Windows with LF:
   ```cmd
   git -c core.autocrlf=false clone https://github.com/wesleytakatsu/TooieRecomp.git C:\src\TooieRecomp
   cd C:\src\TooieRecomp
   git config core.autocrlf false
   ```
3. Extract generated code archive to `C:\temp\RecompiledFuncs`.
4. In Windows PowerShell:
   ```powershell
   .\tools\windows\Build-Tooie.ps1 -Stage Check
   .\tools\windows\Build-Tooie.ps1 -Stage ImportGenerated -GeneratedFrom C:\temp\RecompiledFuncs
   .\tools\windows\Build-Tooie.ps1 -Stage Build
   .\tools\windows\Build-Tooie.ps1 -Stage Package
   ```
5. Place `decompressed.us.z64` in the project root and select it when launching the executable.

### 4.3 Pathway B: Local Generation via WSL2 (Kit-Free)

1. Install WSL2 Ubuntu: `wsl --install -d Ubuntu-24.04`.
2. Inside WSL2, run the kit-free generation stages:
   ```bash
   tools/build_linux.sh preflight verify extract recomp
   ```
3. In Windows PowerShell:
   ```powershell
   .\tools\windows\Build-Tooie.ps1 -Stage Check
   .\tools\windows\Build-Tooie.ps1 -Stage ImportGenerated -GeneratedFrom \\wsl$\Ubuntu-24.04\home\<user>\TooieRecomp\RecompiledFuncs
   .\tools\windows\Build-Tooie.ps1 -Stage Build
   .\tools\windows\Build-Tooie.ps1 -Stage Package
   ```

## 5. Distribution & Licensing

- **Private-Local Classification:** Any package containing `TooieRecompiled` embeds machine-translated game logic derived from the user's ROM; all archives are designated `*-private-local`.
- **Zero Game Assets Versioned:** The repository contains no ROM dumps, textures, level geometry, or audio banks.
- **Native UI Resources:** All previously completed native UI assets, animations, icons, character vector art, typography fonts (including `Suplexmentary Comic NC.ttf`, `InterVariable.ttf`, `NotoEmoji-Regular.ttf`, and `promptfont.ttf`), and the original 7300x2450 Tooie logo are vendored locally in `assets/` and `ui_assets/` (managed on every build by CMake target `TooieUIAssets`). License notices and provenance are tracked honestly (SIL OFL 1.1 notices; zlib controller DB; origin and unverified license status of Suplexmentary Comic NC preserved without blocking restoration).
- Detailed legal terms: See [Asset and Licensing Manifest](../docs/specs/Tooie/asset-and-licensing-manifest.md).
