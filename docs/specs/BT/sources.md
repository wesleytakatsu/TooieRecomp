# BT — Source Tree

Layout of `banjo-tooie-Recomp/src/` (generated by Splat), organized by memory
segment.

## Top level

```
src/
├── boot/       # entry point, exception handlers, OS init
├── core1/      # main loop, memory manager
├── core2/      # overlay loading, RSP/audio mgmt
├── overlays/   # per-overlay shared code
└── buffers.c   # fixed DRAM buffers (gfx task stack, etc.)
```

## core1

- `heap.c`, `memory.c`, `defrag.c`, `crc.c` — memory management + checksums
- `idle.c` — boot/thread setup
- `core1bss1_*.s` — manual bss asm
- hundreds of `0x…c.c` files — address-named matched functions

## core2

- address-named functions (`1E64F00.c` … `1E7AB30.c`, etc.)
- contains the main game update loop and overlay loading

## overlays/

Grouped by prefix `ch`, `ca`, etc:

```
overlays/…
  ba/  # player movesets (egg/move)
  bs/  # banjo states  (ban, drone, kazooie, mumbo)
  ch/  # characters: anglerboss, booth, gates, …
  gs/  # jiggy spawn code
  gl/  # world loading
  fx/  # particle/effects
  nc/  # cutscene actors (nc…)
  pl/  # player control
```

Each subfolder uses the overlay name:

```text
overlays/gs/
  attract.c  maker.c prop…  # '#pragma GLOBAL_ASM' stubs in most
```

## C files

The decompilation style is:

```c
#include "common.h"

#pragma GLOBAL_ASM("asm/nonmatchings/overlays/gs/attract/gs_entrypoint_0.s")
```

Matched functions are hand-decompiled C; unmached functions stay as
`#pragma GLOBAL_ASM` pointing into `asm/nonmatchings/`.

## include

`include/` mirrors the original headers:

- `buffers.h`, `memory.h`, `maps.h`, `gameflags.h`, `player.h`
- `common.h` (base C types & macros)
- per-area subdirs (ba/, bo/) matching overlays
- `ultralib` headers inside `lib/`
