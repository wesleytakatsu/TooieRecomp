# Asset Ownership and Licensing Manifest

## 1. Core Principles & Clean-Room Boundaries

TooieRecomp enforces a strict separation between open-source engine virtualization code and proprietary Nintendo / Rare game data. The repository does not host, distribute, or version proprietary ROM dumps, extracted textures, dialog scripts, audio banks, or raw level models.

```text
+---------------------------------------------------------------------------------+
|                       Clean-Room Recompilation Architecture                     |
|                                                                                 |
|  [User-Supplied ROM] (Proprietary, Private, Unlicensed)                         |
|         │                                                                       |
|         ▼                                                                       |
|  [decomp/ Decompilation Sources & ELF Generation]                               |
|         │                                                                       |
|         ▼                                                                       |
|  [N64Recomp / RSPRecomp Code Generators]                                        |
|         │                                                                       |
|         ▼                                                                       |
|  [RecompiledFuncs/*.c] (ROM-Derived C code - Never Published as Source)         |
|         │                                                                       |
|         ├──────────────────────────┐                                            |
|         ▼                          ▼                                            |
|  [Native Source Code]      [Permissive Engine Runtimes]                         |
|  (TooieRecomp Host Logic)  (RT64 [MIT], N64ModernRuntime [MIT/GPLv3],            |
|                            ultramodern [MIT], RecompFrontend)                   |
|         │                          │                                            |
|         └──────────┬───────────────┘                                            |
|                    ▼                                                            |
|          [TooieRecompiled Executable]                                           |
|          (Binary embeds ROM-derived translated logic;                           |
|           Public binary release; contains no ROM assets, reads ROM at runtime)  |
+---------------------------------------------------------------------------------+
```

### 2.1 Vendored Closure & Third-Party Auditing
- Every third-party source is vendored as regular files under `lib/`, `decomp/`, `assets/`, `recompcontrollerdb.txt`, and `tools/wheelhouse/`.
- Provenance and tracking: `vendor/UPSTREAMS.tsv`, `vendor/patches-applied/ORDER.tsv`, `vendor/BINARIES.tsv`, `vendor/EXCLUDES.txt`, and `vendor/MANIFEST.sha256`.
- Rows marked `UNKNOWN` or `UNVERIFIED` in the third-party manifest remain open owner items to clear (not a block on publishing). TooieRecomp's own code is GPL-3.0 (`LICENSE`, required because the executable links the GPL-3.0
  N64ModernRuntime); ROM-derived code, `decomp/` and game content are not covered.

## 4. Packaging and Redistribution Policy

1. **Automated Manifest Enforcement (`THIRD-PARTY-MANIFEST.tsv`)**:
   - Packager runs `tools/package_manifest.sh` backed by rule table `tools/package_licenses.tsv`.
   - Every staged file is inventoried with path, hash, size, category, origin, and license status.
   - Any staged file lacking a matching rule fails the package build immediately (`exit 1`).
   - Separate rules identify pt-BR translation data and proprietary FR/DE/ES localized text. Both are classified as `translation`; this classification is not licence clearance.
2. **Public Release Policy**:
   - Binary releases are public on GitHub Releases (modeled after Zelda64Recomp and BanjoRecomp).
   - Executables contain machine-translated code generated via static recompilation (`RecompiledFuncs/`); source files remain untracked in git and are never published as source.
   - ROM images remain excluded. Historical public packages contain no original game assets. Local packages containing generated FR/DE/ES bundles include proprietary localized text; their inventory must state that fact, and no public release of these bundles was performed by this implementation.
   - The former "private-local" designation and `-private-local` archive suffix are removed.
   - Package naming:
     - Release: `Build-Tooie.ps1 -Stage Package -ReleaseVersion <ver>` produces `dist\BanjoTooieRecompiled-v<ver>-Windows-x64.zip`; Linux `TOOIE_RELEASE_VERSION=<ver> tools/package_linux.sh` produces `dist/BanjoTooieRecompiled-v<ver>-Linux-x64.tar.gz`.
     - Development: builds without a release version produce `BanjoTooieRecompiled-dev-<git describe --always --dirty>-Windows-x64.zip` / `-Linux-x64.tar.gz`.
     - Structure: Each archive contains a single top-level `BanjoTooieRecompiled/` folder with `BUILD-INFO.txt` (recording exact commit/dirty state and `release_version`), and `README-PACKAGE.txt`; a `<archive>.sha256` sidecar sits next to the archive.
   - `README-PACKAGE.txt` is written for end users: explains project scope, requires user's own ROM (SHA-1 verified), instructions on how to play, settings/saves persistence locations, legal notice (Banjo-Tooie © Nintendo/Rare, unofficial fan project, not affiliated; executable contains translated code; use a ROM from an owned cartridge; third-party licenses in `licenses/` and `THIRD-PARTY-MANIFEST.tsv`), checksum verification, and upstream repository URL (`https://github.com/wesleytakatsu/TooieRecomp`).
   - First public-ready release: GitHub release `v0.1.0-p08` (`BanjoTooieRecompiled-v0.1.0-Windows-x64.zip`, Windows validated; Linux package naming change not run yet — validated by owner on a separate PC).
3. **Package Content Audit Invariant**:
   - Distribution packages are validated by `tools/verify_package.py`.
   - Prohibited files: `.z64`, `.n64`, `.v64`, `.elf`, `.sav`, `.eep`, `.log`, `baserom*`, `decompressed*`.
   - Any `*.json` file at the root of the distribution package is forbidden, and configuration files (`graphics.json`, `general.json`, `sound.json`, `controls.json`) must never be bundled anywhere in the archive.
   - All third-party licenses are aggregated into the package `licenses/` directory; rows marked `UNKNOWN` or `UNVERIFIED` in `THIRD-PARTY-MANIFEST.tsv` remain open owner items to clear. The project's GPL-3.0 text ships at the package root as `LICENSE.txt`.
