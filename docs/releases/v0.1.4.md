# Banjo-Tooie Recompiled v0.1.4

## English

Windows x64 pre-release based on the merged `main`, including PR [#1](https://github.com/wesleytakatsu/TooieRecomp/pull/1).

### Changes since v0.1.3

#### More graphics options and automatic startup fallback

- Integrated **TK64**, adding **DirectX 11 and desktop OpenGL 4.3** alongside DirectX 12 and Vulkan.
- Choose **Auto / DX12 / Vulkan / DX11 / OpenGL** under **Settings → Graphics → Graphics API**. Apply saves your
  preference for the next application launch; the running renderer is not replaced during gameplay.
- On Windows, Auto tries **DX12 → Vulkan → DX11 → OpenGL** until a backend initializes successfully, while retaining
  driver compatibility rules and Wine's Vulkan preference. An explicit API is tried first, with alternatives if it fails.
- Failed startup attempts are isolated before the launcher becomes visible. The description reports the actual API
  in use. Optional graphics diagnostics are available when investigating startup problems.
- OpenGL requires **desktop OpenGL 4.3 or newer**; this release does not add an OpenGL 3.x path.

#### Launcher and window behavior

- Removed the hidden game instance previously used to provide launcher music. Normal gameplay now starts through
  **Start Game**.
- Launcher music uses an independent MP3 player with loop support, Master/BGM volume and a fade before game audio starts.
  It reads the user's local pause-music file; **no recording is included**, so a fresh installation without that file is silent.
- Removed the launcher music-selection button and the graphics selector over the launcher artwork. API selection lives
  in Graphics.
- Fixed windowed/fullscreen persistence when switching with F11 or Alt+Enter, and prevented mode changes from exposing
  hidden windows.

#### Smooth analog camera

- **General → Analog Camera** now provides continuous right-stick third-person camera movement in supported story cameras.
- Movement is smooth and proportional to stick deflection, with working sensitivity and horizontal/vertical inversion.
  Camera speed uses simulation time rather than presentation FPS.
- **Hold N64 Z** to restore the original C-button actions on the stick, including remapped Z bindings.
- First-person aiming restores native C controls, including left/right zoom. Special modes such as Breegull Blaster,
  dedicated minigames and unsupported camera controllers retain their original controls.
- Each split-screen player has independent camera input and smoothing.

#### Object distance and widescreen fixes

- Added **Graphics → Object Distance: Original / 2x / 4x / Unlimited**, saved between sessions and applied without restarting.
  Original remains the default.
- Extended object selection, actor updates and model/sprite visibility together so supported enemies, collectibles and
  props can appear farther away while retaining their gradual distance fades.
- Split-screen distance updates consider the closer player. Unlimited removes the covered radial limits; walls, sectors
  and object-specific conditions can still hide entities, and higher settings may increase CPU/GPU load.
- Fixed stretched story cinematics such as Jamjars' ability explanations while respecting the current window aspect ratio.
- Fixed partial clipping of eggs, feathers, enemies and shadows in the extra widescreen areas at certain camera angles.
- Fixed an independent projection-command buffer overwrite discovered during that investigation.

#### Experimental two-player story split screen

- Added **Dev Mode → Two players (split screen)**, off by default. Unlock Dev Mode, enable Multiplayer in General and
  assign two players/controllers in Controls. Player creation changes take effect on the next eligible map load.
- Both players have their own character and camera, can collect items and attack, and share inventory and map transitions.
  J2 is placed near J1 on entry and follows Dev Mode Warp teleports.
- Fixed lighting/color interference between the two player models.
- Fixed a distant J2 repeatedly collecting the same Glowbo without it disappearing.
- Added J2 targeting to **eight supported enemy families**, including the ground/flying enemies investigated in Jinjo Village.
- Fixed Warp Pad/Silo destination lists disappearing when J2 is far from J1. Their operation remains J1-only.
- Added split-screen suspension when loading the covered rooms for **15 minigame families / 23 stages**, related variants
  and Saucer of Peril segments. Native event controls are preserved; J2 returns on the next eligible map creation.
- Improved player/controller ownership across loading, retries and transitions so old shortcut presses or camera samples
  do not carry into recreated players.

#### Per-player character selection and Dev Mode controls

- Added an independent selector with **17 character/form entries**, opened through **Open for Player 1/2** or a configurable
  Debug Button + D-pad shortcut. Each list stays inside its player's viewport and consumes only that player's input.
- Forms include Banjo/Kazooie and Dragon variants, solo characters, Mumbo, Snowball, Bee, Washing Machine, Stony,
  Breegull Blaster, Submarine, Golden Goliath, Detonator, Van and small/large T. rex.
- Fixed direct normal-to-Dragon appearance changes and improved per-player form handoff between maps.
- Golden Goliath receives its native **120-second** entry duration. Clockwork Kazooie is excluded from the selector after
  a crash found with that replacement path; the original Clockwork egg mechanics remain unchanged.
- Fly and Breegull Blaster shortcuts now act on the player who presses them, with separate requests and model cleanup.
  Physical R3 or the mapped Debug Button works; R3 / keyboard T are the default Debug Button bindings.
- Reorganized the Dev Mode cards, descriptions, D-pad dropdowns and equal-width player buttons, with vertical scrolling.

#### Maintenance and features carried forward

- Removed temporary development logs, measurement hooks, unused counters and dead code from the reviewed paths.
  Useful diagnostics remain opt-in; automated regression tests are separate from the game executable.
- Consolidated documentation and retired obsolete implementation plans.
- Earlier releases' **saved-position Warp**, **Fly/Breegull Blaster tools**, **plain ZIP RT64 texture packs** and
  **dense-scene rendering optimizations** remain included. These are carried forward, not newly introduced in v0.1.4.

### Known limitations

- Story split screen is experimental. J1 still handles doors/map changes and travel pads; J2's death affects the shared life.
  Two Golden Goliaths share the native timer. Enemy targeting is not implemented for every enemy or boss.
- **The train/cart race with the bird still allows J2.** Its suspension was deferred. Room-based suspension is not a
  universal detector for every activity, and the full minigame matrix has not been manually verified.
- The eight enemy families, character forms and extended object distance do not imply exhaustive map/campaign coverage.
  The travel-menu fix has automated coverage; its specific visual acceptance remains pending in the project documentation.
- New backends need broader GPU/driver testing and do not provide MSAA in their new rendering paths. Intro-wall and
  ultrawide residual issues remain. Automatic process-level recovery is implemented on Windows.
- The synchronized in-game MP3 music ZIP mod from the separate audio branch is **not included**. The independent launcher
  music player is a different feature.

### Validation and downloads

- All **30 required Windows host tests passed**, and a new Release executable was built for this version.
- Generated-source integrity and vendored-source checks passed. The Windows ZIP passed the content, license-mapping,
  manifest and SHA-256 audits.
- User gameplay tests on Windows cover the reported fixes, not every map, event, form or GPU. This publication does not
  claim a new exhaustive manual campaign or four-API hardware test.
- Download **`BanjoTooieRecompiled-v0.1.4-Windows-x64.zip`** and its **`.sha256`** sidecar. Extract the ZIP and run
  **`TooieRecompiled.exe`**. Your own **Banjo-Tooie (USA) rev 0 ROM** is required.
- ROMs, private music, texture packs, saves and personal configuration are not included.
- No Linux v0.1.4 package is included; the previous Linux packages remain available in **v0.1.0-p08**. Linux runtime
  acceptance for these features remains pending.

## Português Brasileiro

Pré-release Windows x64 baseada na `main` mesclada, incluindo a PR [#1](https://github.com/wesleytakatsu/TooieRecomp/pull/1).

### Mudanças desde v0.1.3

#### Mais opções gráficas e alternativas automáticas na inicialização

- Integração do **TK64**, acrescentando **DirectX 11 e OpenGL desktop 4.3** às opções DirectX 12 e Vulkan.
- Escolha **Auto / DX12 / Vulkan / DX11 / OpenGL** em **Settings → Graphics → Graphics API**. Apply salva a preferência
  para a próxima abertura; o renderizador não é trocado durante a sessão.
- No Windows, Auto tenta **DX12 → Vulkan → DX11 → OpenGL** até inicializar uma API, respeitando as regras de drivers e a
  preferência do Wine por Vulkan. Uma API escolhida explicitamente é tentada primeiro, com alternativas se falhar.
- Tentativas malsucedidas ficam isoladas antes de o launcher aparecer. A descrição informa a API realmente utilizada.
  Há diagnóstico gráfico opcional para investigar problemas de inicialização.
- OpenGL exige **OpenGL desktop 4.3 ou superior**; esta versão não acrescenta um caminho OpenGL 3.x.

#### Launcher e modo de janela

- Removida a instância oculta do jogo usada anteriormente para produzir música no launcher. Em uso normal, o jogo
  começa ao selecionar **Start Game**.
- Música do launcher reproduzida por um player MP3 independente, com loop, volume Master/BGM e fade antes do áudio do jogo.
  Usa o arquivo local de música de pausa do usuário; **nenhuma gravação acompanha o pacote**, portanto uma instalação
  nova sem esse arquivo fica silenciosa.
- Removidos o botão de selecionar música e o seletor gráfico sobre a arte do launcher. A escolha da API fica em Graphics.
- Corrigida a persistência de janela/tela cheia ao usar F11 ou Alt+Enter e impedida a exposição de janelas ocultas na troca.

#### Câmera analógica suave

- **General → Analog Camera** passa a movimentar continuamente a câmera em terceira pessoa com o analógico direito,
  nas câmeras compatíveis do modo história.
- Movimento suave e proporcional à intensidade da alavanca, com sensibilidade e inversão horizontal/vertical funcionais.
  A velocidade usa o tempo da simulação, sem depender do FPS de apresentação.
- **Segurar o Z do N64** restaura os comandos C originais na alavanca, inclusive quando Z foi remapeado.
- A mira em primeira pessoa restaura os comandos C, incluindo aumentar/diminuir o zoom. Modos especiais como Breegull
  Blaster, salas dedicadas de minigames e controladores de câmera não compatíveis mantêm os controles originais.
- Entrada e suavização independentes para cada jogador no splitscreen.

#### Distância de objetos e correções no widescreen

- Nova opção **Graphics → Object Distance: Original / 2x / 4x / Unlimited**, salva entre sessões e aplicada sem reiniciar.
  Original continua sendo o padrão.
- Ampliação coordenada da seleção de objetos, atualização dos atores e visibilidade de modelos/sprites, permitindo que
  inimigos, coletáveis e elementos cobertos apareçam mais longe sem perder o fade de distância.
- No splitscreen, a atualização considera o jogador mais próximo. Unlimited remove os limites radiais cobertos; paredes,
  setores e condições próprias ainda podem ocultar objetos. Distâncias maiores podem aumentar a carga de CPU/GPU.
- Corrigido o esticamento de cenas do modo história, como explicações de habilidades do Jamjars, respeitando a proporção
  atual da janela.
- Corrigidos cortes parciais de ovos, penas, inimigos e sombras nas áreas extras do widescreen em certos ângulos de câmera.
- Corrigida uma sobrescrita independente do buffer de comandos de projeção encontrada durante essa investigação.

#### Cooperativo experimental para dois jogadores no modo história

- Nova opção **Dev Mode → Two players (split screen)**, desligada por padrão. Desbloqueie Dev Mode, ative Multiplayer em
  General e atribua dois jogadores/controles em Controls. A criação muda no próximo carregamento de mapa elegível.
- Dois personagens e câmeras independentes, com coleta, ataques, inventário e transições de mapa compartilhados.
  J2 aparece próximo de J1 e acompanha os teleportes do Warp do Dev Mode.
- Corrigida a interferência de iluminação/cores entre os modelos dos dois jogadores.
- Corrigido o Glowbo que podia ser coletado repetidamente por J2 distante sem desaparecer.
- Adicionado reconhecimento de J2 como alvo em **oito famílias de inimigos**, incluindo os terrestres/voadores
  investigados em Jinjo Village.
- Corrigido o desaparecimento das listas de destinos de Warp Pads/Silos quando J2 está longe. Esses transportes continuam
  sendo operados apenas por J1.
- Suspensão do splitscreen ao carregar as salas cobertas das **15 famílias de minigames / 23 estágios**, variantes
  relacionadas e trechos de Saucer of Peril. Controles nativos preservados; J2 retorna na próxima criação elegível.
- Melhorado o vínculo entre jogador e controle em carregamentos, novas tentativas e transições, evitando reaproveitar
  atalhos pressionados ou amostras antigas de câmera em personagens recriados.

#### Seleção de personagens por jogador e controles do Dev Mode

- Seletor independente com **17 opções de personagem/forma**, aberto por **Open for Player 1/2** ou pelo atalho configurável
  Debug Button + D-pad. Cada lista fica na tela de seu jogador e consome apenas os comandos dele.
- Inclui Banjo/Kazooie e variantes Dragon, personagens separados, Mumbo, Snowball, Bee, Washing Machine, Stony,
  Breegull Blaster, Submarine, Golden Goliath, Detonator, Van e os T. rex pequeno/grande.
- Corrigida a troca direta da aparência normal para Dragon e melhorada a passagem individual das formas entre mapas.
- Golden Goliath recebe os **120 segundos** iniciais nativos. Clockwork Kazooie foi excluído do seletor após um crash
  nesse caminho de substituição; a mecânica original dos ovos Clockwork permanece igual.
- Atalhos Fly e Breegull Blaster atuam no jogador que os acionou, com pedidos e limpeza de modelos separados.
  Funcionam com R3 físico ou Debug Button mapeado; R3 / T no teclado são os padrões do Debug Button.
- Dev Mode reorganizado com descrições, dropdowns de direção, botões dos jogadores de mesma largura e rolagem vertical.

#### Manutenção e recursos mantidos

- Removidos logs temporários de desenvolvimento, medições, contadores sem uso e código morto nos caminhos revisados.
  Diagnósticos úteis continuam opcionais; testes automatizados ficam fora do executável do jogo.
- Documentação consolidada e planos de implementação obsoletos retirados.
- Continuam incluídos os recursos das versões anteriores: **Warp com posições salvas**, **Fly/Breegull Blaster**,
  **ZIPs originais de texturas RT64** e **otimizações de renderização em cenas densas**. São recursos mantidos,
  não novidades introduzidas na v0.1.4.

### Limitações conhecidas

- Splitscreen no modo história é experimental. J1 continua responsável por portas/mudanças de mapa e transportes;
  a morte de J2 afeta a vida compartilhada. Dois Golden Goliaths compartilham o timer nativo. A IA não cobre todos os
  inimigos ou chefes.
- **A corrida de trenzinho com o pássaro ainda permite J2.** Sua suspensão foi adiada. A política por salas não detecta
  universalmente qualquer atividade, e a matriz completa de minigames ainda não foi validada manualmente.
- As oito famílias de inimigos, formas e distância ampliada não representam cobertura exaustiva de mapas/campanha.
  Menus de viagem têm regressão automatizada; o aceite visual específico ainda consta como pendente na documentação.
- Novos backends precisam de testes mais amplos de GPU/driver e não oferecem MSAA nos caminhos novos. Restam problemas
  de paredes do intro e ultrawide. Recuperação automática entre processos implementada no Windows.
- O mod ZIP de músicas MP3 sincronizadas da branch de áudio **não está incluído**. O player independente de música do
  launcher é outro recurso.

### Validação e downloads

- Os **30 testes obrigatórios do Windows passaram**, e foi gerado um novo executável Release para esta versão.
- Integridade do código gerado e das fontes vendorizadas conferida. ZIP Windows aprovado nas auditorias de conteúdo,
  mapeamento de licenças, manifestos e SHA-256.
- Testes manuais do usuário no Windows cobrem os casos relatados, sem garantir todos os mapas, eventos, formas ou GPUs.
  Esta publicação não afirma uma nova bateria manual completa da campanha ou de hardware nas quatro APIs.
- Baixe **`BanjoTooieRecompiled-v0.1.4-Windows-x64.zip`** e seu arquivo **`.sha256`**. Extraia e execute
  **`TooieRecompiled.exe`**. É necessária sua própria **ROM Banjo-Tooie (USA) rev 0**.
- ROMs, músicas privadas, pacotes de texturas, saves e configurações pessoais não estão incluídos.
- Linux v0.1.4 não está incluído; os pacotes Linux anteriores continuam disponíveis em **v0.1.0-p08**. O aceite em
  runtime Linux dessas novidades permanece pendente.
