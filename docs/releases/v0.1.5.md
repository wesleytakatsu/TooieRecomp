# Banjo-Tooie Recompiled v0.1.5

## English

Windows x64 and PortMaster (aarch64 Linux handheld) pre-release, built from the `feat/handheld` branch of PR
[#2](https://github.com/wesleytakatsu/TooieRecomp/pull/2).

### Changes since v0.1.4

#### New: PortMaster package for aarch64 handhelds

- First handheld build: **Linux aarch64 with OpenGL ES**, packaged for **PortMaster**. It targets RK3326 handhelds
  such as the **MagicX XU10** and the **R36S**.
- Copy the `Banjo-Tooie.sh` script and the `tooie/` folder to your ports folder, and put your own ROM in the `tooie/`
  folder. On first start, the launcher checks the ROM and prepares it on the device. It warns when the ROM is
  missing or is the wrong one.
- Renderer tuned for handheld GPUs, with both ARM's Mali driver and Panfrost (Mesa). The device keeps a shader cache,
  so later starts are faster.
- The handheld build comes from the same source as the desktop builds: each platform has its own CMake preset.

#### Graphics API menu per platform

- **Settings → Graphics → Graphics API** now lists only the APIs that this build includes and that your device can start:
  - Windows: Auto, DX12, Vulkan, DX11, OpenGL.
  - Linux: Auto, Vulkan, OpenGL.
  - Handheld: Auto, OpenGL ES.
- A value saved on another platform falls back to Auto. On Linux, Auto uses OpenGL when no Vulkan device is found.

#### Lower CPU use in the renderer on every platform

- Unchanged framebuffers are detected on the CPU, so the renderer no longer waits for the GPU to count changed pixels.
- One OpenGL backend for desktop and handheld, with fewer state changes and submissions.
- Measured on Windows (AMD GPU), process CPU in % of one core: **DX12 about 17% → 12%**, **OpenGL about 75% → 51%**,
  still at 58–60 FPS. On the MagicX XU10, from **20 to 23 FPS** in the same scene.

#### Dev Mode Warp modal

- Navigation stays inside the Warp modal: up/down picks a saved position, left/right picks Teleport / Rename / Delete,
  the list scrolls with the focus, the right stick scrolls, and Back/B closes the modal.

#### Build and maintenance

- New Linux x64 packaging scripts: `./build-linux.sh` builds a `.tar.gz`, `.deb`, AppImage or all three, and checks
  prerequisites first.
- Handheld cross build from Windows or Linux hosts (`tools/handheld/`), without WSL.
- CI now cross-builds the handheld renderer and runs its tests under an ARM emulator. Fixed a Windows CI test that
  wrote to a fixed `/tmp` path.
- All features of v0.1.4 and earlier releases remain included.

### Known limitations

- **Handheld:** only the **MagicX XU10 with ROCKNIX** has run this build (Mali and Panfrost drivers). The **R36S** uses
  the same RK3326 chip but has **not been tested**, nor have other firmwares such as ArkOS or dArkOS. Expect about
  **21–24 FPS**, not 60. The first start compiles shaders, which takes time and memory; later starts use the cache.
- **Windows:** the new Graphics API menu, a game run on each of the four APIs and the Warp modal in game have not been
  confirmed on screen for this release.
- **Linux:** the owner built and ran the Linux x64 version and reported that it works (a general report, not per
  API). No Linux package is attached to this release; the previous Linux packages remain in **v0.1.0-p08**, and the new
  scripts build them from source.
- The known limitations of v0.1.4 (experimental story split screen, the train race with the bird still allowing J2,
  intro-wall and ultrawide residuals) still apply.

### Validation and downloads

- All **31 required Windows host tests passed**, the 420 generated files and the vendored sources were verified, and a
  new Release executable was built for this version. The Windows ZIP passed the content, license-mapping, manifest
  and SHA-256 audits.
- The PortMaster package was cross-built, checked against its manifest, installed on a MagicX XU10 (ROCKNIX) and
  started the game on OpenGL ES. Its 9 cross-built host tests passed on the device and under an ARM emulator in CI.
- Downloads:
  - **`BanjoTooieRecompiled-v0.1.5-Windows-x64.zip`**: extract it and run **`TooieRecompiled.exe`**.
  - **`BanjoTooieRecompiled-v0.1.5-Linux-arm64-PortMaster.zip`**: extract it into your device's ports folder
    (for example `roms/ports`), then start **Banjo-Tooie** from Ports.
  - Each file has a **`.sha256`** sidecar.
- Your own **Banjo-Tooie (USA) rev 0 ROM** is required. ROMs, private music, texture packs, saves and personal
  configuration are not included.

## Português Brasileiro

Pré-release para Windows x64 e PortMaster (portáteis Linux aarch64), gerada a partir da branch `feat/handheld` da PR
[#2](https://github.com/wesleytakatsu/TooieRecomp/pull/2).

### Mudanças desde v0.1.4

#### Novo: pacote PortMaster para portáteis aarch64

- Primeiro build para portáteis: **Linux aarch64 com OpenGL ES**, empacotado para **PortMaster**. Feito para portáteis
  com chip RK3326, como o **MagicX XU10** e o **R36S**.
- Copie o script `Banjo-Tooie.sh` e a pasta `tooie/` para a pasta de ports, e coloque sua própria ROM na pasta `tooie/`.
  Na primeira abertura, o launcher confere a ROM e a prepara no próprio aparelho. Ele avisa quando a ROM está faltando
  ou é a errada.
- Renderizador ajustado para GPUs de portáteis, tanto com o driver Mali da ARM quanto com o Panfrost (Mesa). O aparelho
  guarda um cache de shaders, então as aberturas seguintes são mais rápidas.
- O build do portátil sai do mesmo código dos builds de desktop: cada plataforma tem seu preset CMake.

#### Menu de API gráfica por plataforma

- **Settings → Graphics → Graphics API** agora lista só as APIs que o build inclui e que o aparelho consegue iniciar:
  - Windows: Auto, DX12, Vulkan, DX11, OpenGL.
  - Linux: Auto, Vulkan, OpenGL.
  - Portátil: Auto, OpenGL ES.
- Um valor salvo em outra plataforma volta para Auto. No Linux, Auto usa OpenGL quando não encontra dispositivo Vulkan.

#### Menos uso de CPU no renderizador em todas as plataformas

- Framebuffers sem mudança são detectados na CPU; o renderizador não espera mais a GPU contar os pixels alterados.
- Um só backend OpenGL para desktop e portátil, com menos trocas de estado e envios.
- Medido no Windows (GPU AMD), CPU do processo em % de um núcleo: **DX12 de cerca de 17% para 12%**, **OpenGL de cerca de
  75% para 51%**, mantendo 58–60 FPS. No MagicX XU10, de **20 para 23 FPS** na mesma cena.

#### Modal do Warp no Dev Mode

- A navegação fica dentro do modal do Warp: cima/baixo escolhe a posição salva, esquerda/direita escolhe Teleport /
  Rename / Delete, a lista rola acompanhando o foco, a alavanca direita rola e Back/B fecha o modal.

#### Build e manutenção

- Novos scripts de pacote para Linux x64: `./build-linux.sh` gera `.tar.gz`, `.deb`, AppImage ou os três, conferindo
  os pré-requisitos antes.
- Build cruzado do portátil a partir de Windows ou Linux (`tools/handheld/`), sem WSL.
- A CI agora faz o build cruzado do renderizador do portátil e roda seus testes num emulador ARM. Corrigido um teste da
  CI Windows que gravava num caminho fixo `/tmp`.
- Todos os recursos da v0.1.4 e das versões anteriores continuam incluídos.

### Limitações conhecidas

- **Portátil:** só o **MagicX XU10 com ROCKNIX** rodou este build (drivers Mali e Panfrost). O **R36S** usa o mesmo chip
  RK3326, mas **não foi testado**, assim como outros firmwares, como ArkOS e dArkOS. Espere cerca de **21–24 FPS**,
  não 60. A primeira abertura compila os shaders, o que leva tempo e memória; as seguintes usam o cache.
- **Windows:** o novo menu Graphics API, o jogo em cada uma das quatro APIs e o modal do Warp no jogo ainda não foram
  confirmados na tela para esta versão.
- **Linux:** o autor compilou e rodou a versão Linux x64 e relatou que funciona (relato geral, não por API). Esta release
  não traz pacote Linux; os pacotes Linux anteriores continuam na **v0.1.0-p08**, e os novos scripts os geram a partir
  do código.
- As limitações conhecidas da v0.1.4 (splitscreen experimental no modo história, corrida de trenzinho com o pássaro
  ainda permitindo J2, resíduos das paredes do intro e do ultrawide) continuam valendo.

### Validação e downloads

- Os **31 testes obrigatórios do Windows passaram**, os 420 arquivos gerados e as fontes vendorizadas foram conferidos, e
  foi gerado um novo executável Release para esta versão. O ZIP Windows passou nas auditorias de conteúdo, mapeamento
  de licenças, manifesto e SHA-256.
- O pacote PortMaster foi gerado por build cruzado, conferido contra o manifesto, instalado num MagicX XU10 (ROCKNIX) e
  iniciou o jogo em OpenGL ES. Seus 9 testes host gerados por build cruzado passaram no aparelho e num emulador ARM na CI.
- Downloads:
  - **`BanjoTooieRecompiled-v0.1.5-Windows-x64.zip`**: extraia e execute **`TooieRecompiled.exe`**.
  - **`BanjoTooieRecompiled-v0.1.5-Linux-arm64-PortMaster.zip`**: extraia na pasta de ports do aparelho
    (por exemplo `roms/ports`) e abra **Banjo-Tooie** em Ports.
  - Cada arquivo tem um **`.sha256`**.
- É necessária sua própria **ROM Banjo-Tooie (USA) rev 0**. ROMs, músicas privadas, pacotes de texturas, saves e
  configurações pessoais não estão incluídos.
